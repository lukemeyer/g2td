# G2TD: Tower Defense — notes for the next session

An Even Hub app for the Even Realities G2 glasses. README.md says how it draws and
plays; docs/art.md covers the art. This file is the working state and what was
learned along the way.

## Where things are

- **`src/maps.json`:** the campaign, six maps in order: anchors, slots, waves, credits,
  enemy health factor (`hp`), art theme, `msgBox`, and the boss's script. It is the one
  list for the game, the balance tool and the art tools.
- **`src/rules.ts`:** all game rules (maps, slots, towers, enemies, the step/phase
  machine, the boss), with no display code.
  - `useMap(i)` makes a map current and rebuilds everything map-dependent as exported
    `let`s (ES live bindings).
  - `tools/balance.ts` runs it headless.
- **`src/bot.ts`:** the balance bots, shared by tools/balance.ts and the random map.
- **`src/main.ts`:** text layers, the map image, input, the bridge, the long-press menu.
- **`src/phone.ts`:** the phone page.
  - Guide: gameplay, controls, enemies, towers, maps. The text is the user's own, kept
    in docs/guide.md; edit both together.
  - Stats: the map without enemies, per-wave kills, damage and leaks, per-tower totals.
- **`src/random_map.ts`:** the random map, the last entry of MAPS after the campaign
  (`CAMPAIGN_LEN`, `RANDOM_INDEX`).
- **`src/sprites.ts`:** generated by `tools/import_sprites.py` from `art/sprites/<id>.png`
  (the picks). Don't edit by hand.
- **Maps:**
  - Drawn by `src/render/map.ts` from the art pack (`art/pack/`, bundled into
    `src/pack.ts` by `tools/pack_build.py`).
  - Layouts are `art/maps/<id>/layout.json`, bundled by `src/render/layouts.ts`.
  - See docs/art.md.
- **Map editor** (dev only):
  - URL: `npm run dev`, then http://localhost:5173/tools/map-editor/?map=hab-ring.
  - Draws with the game's renderer.
  - Pieces mode: tap a palette piece for a stamp; tap or drag to place. R or ⟳ turns.
    Tap a placed piece to select and drag it; Delete removes it. ◇ Variant or V changes
    the variant. The palette filters by map or shared.
  - Floor mode paints floor tiles. Walls mode toggles the wall nearest the pointer.
    Eraser (E).
  - Nothing may stand on the road, the HUD box or the boss. The editor doesn't block the message box (the game draws over it).
  - The margin columns (-1 and 21) take floor, decals, pieces and walls, except under
    the road or the HUD.
  - Save posts to `/__editor/save` (`devTools` in vite.config.ts), which writes only
    the layout file.
- **Art library** (dev only):
  - URL: http://localhost:5173/tools/art-library/?map=shared:furniture.
  - Every pack picture as the renderer draws it, per shared group and per map, plus the
    candidates in `art/work/` with "use".
  - `art/work/` and `art/reviews.json` are local and ignored by git; a fresh clone has
    no candidates. The art library's "use" copies a candidate into the pack.
- **`art/reference/couch-s1.png`:** the house-style reference for every generation.
- **`store/`:**
  - `listing.md` and `description.txt`;
  - the icon `icon.png`, drawn by `make_icon.py`: three drones in formation, 24x24
    in 2x2 blocks;
  - `screenshots/`.
- **Docs:**
  - `docs/messages.md`: every message line with its width.
  - `docs/guide.md`: the phone guide's text.

## Commands

```bash
npm run dev                 # vite on :5173
npx evenhub-simulator --automation-port 9898 http://localhost:5173        # ?map=3: start on map 3 (1-based, 20 lives); ?w=6: start the first map before wave 6 with every slot built
npm run balance             # node tools/balance.ts (every map); node tools/balance.ts 6 for one map
npm run check               # tsc, build, balance, pack
npm run play                # the browser playtest on :5174/play.html; npm run build:play writes dist-play/
npx evenhub pack app.json dist -o g2td-<version>.ehpk --sdk-ver 0.0.16
npx evenhub upload g2td-<version>.ehpk -m "what changed"    # private build; bump version in app.json AND package.json first
npx evenhub promote <version> --to beta --package-id com.elsethenif.g2td
```

- **Python tools:** they need Pillow, which the system Python doesn't have.
  `python3 -m venv .venv && .venv/bin/pip install pillow`, then run them with
  `.venv/bin/python -I`.
- **Even Hub CLI:**
  - Signed in as the developer account (namespace 2850). If an upload says "Refresh
    token invalid", the user runs `npx evenhub login`.
  - App `com.elsethenif.g2td`.
  - Private builds install from the Even Hub tab (Developer Mode) → Me → Apps →
    Private builds, and don't show in the glasses menu.
  - A beta build can be installed by active testers in the Even app.
  - `app.json` `min_sdk_version` matches the SDK built against (0.0.16).
- **Acceptance rules the app keeps (Even Hub):**
  - 12 containers at most (8 text + 4 image tiles of 288x144);
  - exactly one `isEventCapture`;
  - unique ids and names, names of 16 characters or fewer;
  - `zOrderIndex` on every container;
  - no network; permissions `[]`;
  - text under 1000 characters.
- **Simulator automation** (port 9898):
  - `/api/screenshot/glasses`: RGBA, brightness is in alpha; composite on black to
    look at it.
  - `/api/console`.
  - POST `/api/input` with `up`, `down`, `click`, `double_click` or `context_menu` (a
    long press; then `down`… `click` picks a menu item).
- **Simulator storage** is empty every time it is launched. A page reload (Vite reloads
  on source changes) keeps it, so test resuming that way.

## The design (decided with the user)

**Grid and drawing**
- Cells are a 20 px glyph and one 5 px space apart (`GAP`, the glasses font's only space
  glyph), rows 27 px apart.
  - Pads are 45x47.
  - The 520 px grid is centred (`X0` = 25).
  - A road entering at column 0 or leaving at the last column runs on to the screen's
    edge.
- **Layers:**
  - The map image is 4 tiles.
  - Enemies are baked into every road cell; text covers (`█`, textColor 0, matching
    image level 3) hide all but the occupied cells.
  - Text layers: cover (0), idle tripline lines (1), fx (4: shots, cursor, reach dots,
    turret rings), an offset layer half a row lower, engrave, input, the HUD box, msg.
- **Input** goes to a text container holding only a space, behind the map (`input`,
  zOrder 0), as the Even notes advise for image apps.
- **Enemies can't grow past 20x20:** anything outside the cover would always show.

**Towers and enemies**
- Triplines (laser, stasis): two posts and a thin line across a straight. Laser fires
  every other step, so enemies can slip past. Stasis slows to a third for 7 steps
  (`SLOW_FACTOR`, `SLOW_STEPS`).
- Turrets (sniper range 4, cannon range 2 with splash): 2x2 pads past a corner, facing
  exactly one straight. The shot comes from the barrel on the target's lane.
- Cannon splash: the target's cell and every road cell touching it, diagonals included.
- Each step is three frames of 250 ms (at 1x): move, aim, hit. Hits are cut into the
  enemy's core (┃━ laser, ▒ stasis, ┼ sniper, ╳ cannon). There's no health indicator.
- Drones (`floater` / `shield` in the code) carry an invisible shield that takes the
  first damaging hit (stasis passes through). Their shadow is their own outline moved
  down and right.
- Walkers trot: three poses with the legs swung 22° about the hip (`stride` in
  import_sprites.py).
- Towers get a dark halo, not an outline (`outlined` in main.ts, `HALO`), never over
  another tower.
- Slot marks (`MARKS` in main.ts) are at level 14 with a dark pixel round them; corner
  brackets go round every slot while building.
  - Built tripline posts are their 24x24 sprites; built turrets keep their sprites.

**Waves and maps**
- A road map is 5 waves, each climbing `pace` (2) steps of the old 10-wave curve
  (`levelOf`), with $200 to start. Each map's `hp` factor is tuned with the balance bots
  so their best plan just about wins.
- Every 4th wave of a road map is a swarm (`SWARM_EVERY`, `isSwarm`, `SWARM`,
  `swarmSize`): walkers only, both lanes side by side, in packs. It exists because
  cannons were never needed without it.
- Lane flips are re-rolled every wave and never repeat the last wave's.
- Automatic slots:
  - Every map but Hab Ring takes the rules' automatic slots: a pad past every corner in
    line with each stretch, then triplines on straights.
  - Triplines in a one-row gap go in pairs per road (`autoSlots`).
- Campaign:
  - Clearing a map loads the next with the towers gone, lives carried over plus 5 (up
    to 20) and the map's own credits.
  - Losing replays the map with the lives it was entered with (at least 6).
  - Beating the boss starts over at map 1.
- Saving: the campaign (`g2td.campaign`) and the game (`g2td.game`, between waves only)
  are saved after every wave, build and removal, and on exit. A wave cut short starts
  again.
- Random map:
  - A left-to-right road, kept only if it has 22-44 squares, 4-8 pads and 6-12 triplines
    and room for the whole message box.
  - `hp` is bisected with the bots.
  - Endless waves (`WAVE n/∞`).
  - Its surroundings are a random road map's kit, scattered.
  - Kept as `g2td.random` to resume.

**The boss (the Airlock)**
- One road: out of the boss along rows 2-3, down cols 17-18, back west along rows 6-7
  and out the left edge.
- Three arms take turns, walkers, drones and a swarm (`boss.arms`). After every wave the
  boss turns clockwise to its next living arm (`turnBoss`, `g.turns`, `socketOf`). Each
  arm's waves grow by its own count (`g.armWaves`).
- Each arm takes 3 hits (`hp` counts hits), shown as one ━ per hit left (`armBar`).
- Only the boss pad ([2,19], facing west up the first straight, `Slot.boss`) hits an
  arm, and only in the mid-wave cooldown:
  - half way through each wave the boss holds back its bots until the road is clear;
  - then until the boss pad has hit the arm `hits` (2) times (`g.cool`);
  - with nothing on the boss pad, the cooldown ends as the road clears.
- A destroyed arm drops its queued bots, pays `turn` (60) at the wave's end, and shows
  as a stump. All three destroyed wins.
- The arm's death plays an explosion (`explode`, `BOOM`) while the stump's tile is sent.
- $140 to start, 6 lives. Tuned with `node tools/balance.ts 6`: the plan that changes
  with the arm wins with 4 lives in 6 waves. Wave 1 is hard on purpose.
- The boss is drawn by `drawBoss`: its body plus an arm sprite per socket (`SOCKETS`,
  read off the body picture: re-read them if the body is re-picked).

**Screen text**
- HUD: a 2-line box top right (`HUD_BOX`: rows 0-1, cols 17-20, `BOX_W` 115 px).
  - Line 1: lives and credits.
  - Line 2: `WAVE 3/5` while building (on the boss map, the coming arm: `WALKERS`,
    `DRONES`, `SWARM`), `BOTS 15/20` during a wave, or `FAST ON` / `FAST OFF` for 4 s.
  - Numbers are padded to a fixed width with `getTextWidth`.
- Messages: the wording is the user's (docs/messages.md); keep the capitalisation.
  - One line, bright (textColor 4), in a dark box the map draws: rules' `MSG_BOX`, one
    row of 11 cells, level 0 with a frame at 6.
  - Placement is per map, aligned by the user so it moves little:

    | Map | Row | Cols |
    |---|---|---|
    | Cargo Bay | 2 | 0-10 |
    | Regolith Mine | 2 | 0-10 |
    | Reactor | 2 | 8-18 |
    | Airlock | 2 | 8-18 |
    | Hab Ring | 0 | 5-15 |
    | Hydroponics | 3 | 11-21 |

  - A map's `msgBox` places the box, checked against slots, HUD and boss; otherwise
    `messageBox` picks a place.
  - The box shows between waves, after game over or a win, and while Restart or Choose
    map is open, mid-wave too (the map is resent; the game waits).
  - The road under it has no covers and no tripline lines.
  - Sending a wave sends the box's tile last, so `Wave N incoming` stays readable.
  - During a wave there's no message.
- Cursor:
  - Swipe up moves along the road (`standingOrder()`), skipping slots built in earlier
    waves; after building, it jumps to the next free slot.
  - On Start Wave, a blinking ◇ marks the road's start.
  - A tower built since the last wave started can be removed for a full refund
    (`g.fresh`, `unbuild`) until the next wave. There's no selling and no swapping.
- Long-press menu: Start Wave, Fast Mode, Choose map, Restart.
  - Fast Mode toggles 4x (`g2td.fast`); waves run at 2x (`NORMAL_SPEED`), building at
    1x.
  - Choose map: `Map ↕ 3 Regolith Mine`, tap starts it with full lives.
  - Restart asks `Restart? ↕ NO / THIS MAP / ALL MAPS`.
  - The menu sends foreground events in the simulator, so don't redraw on them; they
    only save.
- Exit (Even Hub's rule): a double tap always calls `shutDownPageContainer(1)`, the
  glasses' own exit dialog, and saves.
  - Never mode 0, never an in-app confirmation.
  - An open choice is dropped. Nothing plays while `exitAsked`; the first input after
    it only cancels the exit and rebuilds the page (`repaint`).
  - Six refused text updates in a row also trigger `repaint`.

## Brightness (measured on the glasses with a test card, 2026-10-30)

- Image level 0 is black and 1 the first visible. Steps are big up to 6 and small above,
  but still there (15 is clearly brighter than 12 side by side). 1 px lines and lone
  pixels show at every level: busy art reads as noise, not as invisible.
- The text colours are image levels: 0 = 3, 1 = 6, 2 = 9, 3 = 12, 4 = 15.
  - Everything the player reads is textColor 4.
  - The road covers are 0 and must match the road at image level 3.
  - The built tripline's line is 1.
  - Art uses 0-14 (`LEVEL_MAX`), one below the text.
- The simulator differs: textColor 0 shows at about level 8 there, and levels above 9 all
  look the same. Judge brightness, speed and contrast on the glasses, not the simulator.
- No dithering: it only added grain.

## Learned on the real glasses

- Walking enemies turned per cell look good, and so does the cannon's ※ splash with the
  ╳ cut into enemies.
- Free-angle laser beams looked bad (steep beams came out as beads), which is why lasers
  are triplines.
- Frame timing:
  - Wait for a flush already under way.
  - A hidden page's timers fire about once a second, so the loop runs on a Worker's timer.
  - Every bridge call times out (2 s, image tiles 8 s) so one hung call can't stall the
    queue.
  - A failed map tile is resent (up to 3 passes) before a wave starts.
- **Glyphs:**
  - These draw nothing in the glasses font: ╴╶╵╷ ◉ ▢ ◜◝◞◟ ◠◡ ∙ ▪ ◦ ✕ ✗ ⊘ ⚠ ✓.
  - These exist: ╳ × ○ □ ■ ▣ ◇ ∞ ※ ━ ─ │ ┃ ▒ █.
  - `getAdvW(codepoint)` from `@evenrealities/pretext` returns 0 for a missing glyph.
  - Fullwidth digits read as "2 0".
- The background-state API (`setBackgroundState`) isn't in SDK 0.0.16, so a hidden
  WebView resumes from the saves.

## Art generation: Unsloth Studio

- **Setup:**
  - The MCP server is at user scope in `~/.claude.json` (`http://127.0.0.1:8888/mcp/`).
  - Auth comes from a headersHelper script that reads the key from the macOS Keychain.
- **Model:** FLUX.2-klein-4B (Apache 2.0): txt2img, `reference` and inpaint.
  - Studio's memory check refuses it, so load it through the HTTP API with
    `allow_oversized_load` (`POST /api/inference/images/load`).
  - Reloading klein in the Studio UI can drop `reference`; reload it through the API.
- **Inputs:** send 8-bit PNGs; 4-bit ones come back as streaks. Studio's largest image is
  1024x1024.
- **Hangs:** generations can hang for hours, so always time-limit and cancel
  (`tools/studio_gen.py`).
- **How klein behaves:**
  - It never partially denoises (img2img strength makes no difference).
  - `reference` keeps a simple flat sketch's shapes where the sketch puts them.
  - It draws pieces at about 70% of their sketch, which is why the conversion fits by one
    factor, centred.
- **Licences:** don't use flux-3-image-klein or FLUX.1-Kontext (restrictive licences).
  Antigravity / Gemini image generation was tried and dropped.
